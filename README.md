# Merge and Split

QGIS 文件合并和区域拆分插件。

## 合并（Merge）

当前版本以“当前打开的 QGIS 工程”为工程1（总文件），不再依赖来源 QGZ/QGS 的数据源路径。

### 核心方式

1. 在 QGIS 中打开工程1。
2. 插件中一次添加多个数据文件夹。
3. 插件扫描每个文件夹中的实际矢量图层文件。
4. 以工程1的图层名称和顺序作为矩阵基准。
5. 同名称图层自动按行对齐。
6. 图层单元默认显示 `图层名 [要素数量]`；悬停可查看几何类型和源文件。几何类型不兼容时显示 `⚠` 并标红。
7. 文件夹列顶部的 `☑ / ☐` 控制整个文件夹是否参与合并。
8. 工程1没有的图层仍然留在它所属的文件夹列中。
9. 双击未匹配图层，可选择“新增图层”或“移至已有图层”。
10. CRS 不同时自动转换几何；来源文件不被修改。
11. 几何兼容性按去除 Z/M 维度后的精确 WKB 类型判断。
12. 字段以工程1为主，字段类型冲突按目标字段类型尝试转换，无法转换的值写 NULL。

### 合并支持的主要数据文件

- SHP
- GeoPackage（GPKG，多图层会尝试逐层读取）
- GeoJSON / JSON
- SQLite
- KML / KMZ
- GML / TAB（由 OGR/QGIS 实际支持情况决定）

## 区域拆分（Split）

1. 启动插件菜单中的 **Split / 区域拆分**。
2. 点击 **绘制区域**。
3. 在地图上左键单击增加节点，左键双击完成多边形，Esc 可取消。
4. 插件先用多边形外包矩形过滤，再使用精确的 geometry.intersects(polygon) 判断。
5. 完成后可选择三种处理方式：

### ① 删除区域内要素

- 处理当前工程的全部矢量图层。
- 与区域相交的要素都会计入。
- 只删除已经开启编辑的图层；未进入编辑状态的图层自动跳过。
- 删除前会二次确认。
- 与原来的独立 Python 删除脚本保持相同的“相交即处理”逻辑。

### ② 另存为 QGZ 工程

- 当前工程必须先保存。
- 自动使用原工程目录和原工程名，生成 **原工程名_split.qgz**。
- QGZ 内只打包 QGS + SHP 及其配套文件，不创建或使用 GPKG。
- 同时在原工程目录同步生成 SHP 数据，文件名为 **原工程名_split_图层名.shp**，并生成 SHX/DBF/PRJ/CPG 等配套文件。
- QGZ 和同步 SHP 都不会修改当前工程和原始数据。

### ③ 导出到文件夹

可选择：

- ESRI Shapefile（SHP）
- GeoJSON
- KML
- GML

默认输出到原工程目录，并按 **原工程名_split_图层名** 命名；也可以手动选择其他输出文件夹。

只有存在相交要素的图层才输出。

## 使用

### 合并

1. 在 QGIS 中打开工程1。
2. 启动 **Merge and Split 1.1.1**。
3. 点击插件菜单中的 **Merge and Split**。
4. 添加文件夹并完成图层映射。
5. 点击“开始合并”。

### 拆分

1. 点击插件菜单中的 **Split / 区域拆分**。
2. 绘制区域。
3. 选择“删除区域内要素”、“另存为 QGZ 工程”或“导出到文件夹”。
4. 执行并检查结果。

### Split 输出规则（v1.1.1）

- QGZ 不再创建或依赖 GPKG。
- 当前工程必须先保存；QGZ 自动生成在原工程同目录，文件名为 原工程名_split.qgz。
- QGZ 内只打包 QGS + SHP 及其配套文件，不使用 GPKG。
- 生成 QGZ 的同时，在原工程目录同步生成对应的 SHP 数据文件，命名为 原工程名_split_图层名.shp，并同步生成 SHX/DBF/PRJ/CPG 等配套文件。
- 文件导出模式默认输出到原工程目录，并按 原工程名_split_图层名 命名。
- 文件格式：SHP、GeoJSON、KML、GML。
